## what these numbers settle
1. An empty `bench_config=` in `godot-4.7.2-smoke.txt` and `gpu-windowed-device-blocker.txt` is not a capture
   artifact. Case E runs the same windowed Vulkan path, with the same flags, through the same redirection, and the
   line reaches both sinks. Cases B and C emit nothing to either sink because they never get to that point.
2. On the built binary neither windowed path reaches the workload's `_ready()`: B dies 32 lines past its own
   device-setup marker, where E is still 72 lines short of the position the harness line occupies upstream's
   stream. The headless paths (A, D) print it in both sinks, so this is specific to bringing up a real device.
3. The two binaries do NOT fail the same way on the Vulkan path. Both show the same refusal (`Error (-3) creating
   module for shader stage ...`, `Condition "!shader_id" is true. Returning: RID()`), but the built binary exits
   139 in about 3 s and upstream's keeps rendering until the 120 s cap kills it (exit 124), and at the full-length
   run in `gpu-windowed-device-control.txt` §B it is still alive at 301 s with 3,759 error lines. The refusal is
   the host's; the early exit is not reproduced by the control and is therefore a property of this build that
   WO-0002 does not explain.
4. On the OpenGL path the control does reproduce the failure class - both binaries exit 139 with no `_ready()`
   line - but not to the same depth: F's log records `Native OpenGL API detected: 3.3: ATI Technologies Inc. -
   Radeon 535 Series` and C's captures stop before that line, so upstream's binary dies inside context creation
   and this build dies slightly earlier in the same startup.
5. F's log also carries `Accessibility: AccessKit driver loaded.` and C's does not, which is the expected
   consequence of `accesskit=no` in the frozen command line and not a defect signal.

## consequence for the increment
   The conclusion that this host cannot yield a GPU frame-time baseline stands: no path on either binary produces
   a frame that survives readback with the scene in it (ISORYN-D-016, `gpu-readback-golden-frame.txt`). What this
   control removes is the sentence that claimed upstream's binary reproduces the built binary's crashes: it
   reproduces the OpenGL crash and the device refusal, and contradicts the Vulkan one. The unexplained early
   segfault on the built binary is recorded as a residual risk of this Work Order and as a gate on adopting the
   frozen command line as CI's reference build.
